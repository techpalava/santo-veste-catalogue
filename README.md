# Santo Veste Catalogue

A responsive product catalogue and quotation-request experience for Santo Veste, a custom and ready-to-wear apparel studio in Lagos, Nigeria.

## Features

- Twelve apparel categories with product imagery and specifications
- Responsive catalogue cards and accessible product-detail drawer
- Category-aware quotation brief prefilling
- Client-side PDF request summary generation
- Customization services and five-step order process
- Santo Veste metadata, error boundaries and responsive navigation

## Technology

- TanStack Start and TanStack Router
- React 19 and TypeScript
- Tailwind CSS 4
- Radix UI primitives
- jsPDF
- Vite and Nitro

## Local development

You need a current Node.js LTS release and npm.

```sh
git clone https://github.com/techpalava/santo-veste-catalogue.git
cd santo-veste-catalogue
npm install
npm run dev
```

The development server URL is printed in the terminal.

## Commands

```sh
npm run dev       # start the development server
npm run build     # create a production build
npm run preview   # preview the production build
npm run lint      # run ESLint
npm run format    # format the project with Prettier
```

The repository also includes `bun.lock`, so Bun may be used if preferred. Keep one package manager per change to avoid unnecessary lockfile churn.

## Project structure

```text
src/
├── assets/catalogue/       Product and editorial imagery
├── components/site/        Santo Veste page sections
├── components/ui/          Reusable UI primitives
├── lib/
│   ├── santo-veste-data.ts Catalogue, services and process data
│   ├── request-prefill.ts  Inquiry-prefill coordination
│   └── request-pdf.ts      Client-side PDF generation
├── routes/
│   ├── __root.tsx          Application shell and global metadata
│   └── index.tsx           Single-page catalogue route
└── styles.css              Tailwind theme and design tokens
```

`src/routeTree.gen.ts` is generated by TanStack Router and should not be edited manually.

## Production checklist

Before publishing the site for customers:

1. Replace the placeholder email, phone, WhatsApp and Instagram values in `src/components/site/Contact.tsx`.
2. Connect the inquiry form to an approved email, CRM or server endpoint. It currently demonstrates the flow without storing or transmitting data.
3. Add a canonical production URL and an absolute Open Graph image after the domain is known.
4. Run `npm run lint` and `npm run build`.
5. Verify the inquiry and PDF flows on desktop and mobile.
